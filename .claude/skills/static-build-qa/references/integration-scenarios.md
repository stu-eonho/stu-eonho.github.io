## 필수 회귀 테스트 상세

시나리오 2와 3은 **아키텍처 원칙 자체의 회귀 테스트**다. 시간이 없어도 생략하지 않는다. 이 둘이 깨진 채 배포되면 이후 모든 카테고리 추가와 글 작성이 조용히 잘못된 결과를 낸다.

### 시나리오 2 — 카테고리 추가

```bash
# 1. 항목 추가
#    src/config/categories.ts 에:
#    { id: 'seminar', label: 'Seminar', labelKo: '세미나', description: '...',
#      icon: 'presentation', order: 4, metaPanel: 'none' }

mkdir -p src/content/posts/seminar
# 2. category: seminar 인 글 1편 작성

npm run dev
# 3~7. 내비에 Seminar가 Notes 뒤에 / /seminar 목록 헤더에 label·labelKo·description
#      / 새 글 카드 노출 / 상세에서 메타 패널 미렌더(metaPanel: 'none')
# 8. /archive 와 /rss.xml 에도 포함

# 9. CRITICAL 판정
git status --short src/pages/
# ↑ 출력이 비어 있어야 통과. 한 줄이라도 나오면 실패

npm run build && ls dist/seminar/index.html
```

**실패 시 의미:** 파생 체인이 끊긴 파일이 있다. `git status`에 나온 그 파일이 카테고리 문자열을 독립적으로 들고 있다는 뜻이므로, `categories.ts`에서 파생하도록 고친다.

검증 후 추가한 항목·폴더·글을 되돌린다.

### 시나리오 3 — 스키마 실패

6가지 위반을 **하나씩** 넣고 매번 빌드한다. 한꺼번에 넣으면 어느 검증이 잡았는지 알 수 없다.

| 조작                                    | 기대 실패 원인                      |
| --------------------------------------- | ----------------------------------- |
| `paper-review` 글에서 `paper` 블록 삭제 | `superRefine` 조건부 검증           |
| `category: unknown-category`            | `z.enum` 위반                       |
| `title` 삭제                            | required 위반                       |
| `slug: my/nested/post`                  | slug 패턴 위반 (단일 세그먼트 강제) |
| `cover`만 지정, `coverAlt` 비움         | 짝 필드 검증                        |
| 전부 복원                               | **성공해야 함**                     |

매번 확인할 것: **종료 코드가 0이 아닌가**, **에러 메시지에 파일 경로와 필드명이 있는가**.

```bash
npm run build; echo "exit=$?"
```

**실패 시 의미:** 스키마가 위반을 경고로 넘기고 있다. 그 상태로 배포하면 메타 패널이 빈 채로 나가고, 아무도 알아채지 못한다.

마지막 항목(전부 복원 후 성공)을 빠뜨리지 않는다. 스키마가 **정상 입력까지 막고 있는지**는 이 단계에서만 드러난다.
