# Side B — 좋아하는 노래·앨범 탭 설계

작성일 2026-10-29. 사용자와의 대화로 확정한 내용과 작성자(Claude)가 정한 내용을 구분해 적는다. 작성자가 정한 항목에는 **[작성자 결정]** 표시를 붙였다. 사용자는 이 표시가 붙은 항목을 뒤집을 수 있다.

## 1. 의도

이 블로그는 연구·학습 기록이자 해외 포트폴리오다. Side B는 그 사람의 다른 면을 보여 주는 작은 탭으로, 좋아하는 노래와 앨범을 커버 카드로 모아 둔다. 이름은 레코드의 B면에서 왔다. 공부 기록이 A면이고 이 탭이 B면이므로, 공부 블로그 안에 음악 탭이 있는 이유가 이름만으로 설명된다.

방문자는 카드를 넘겨 보며 이 사람의 취향을 가볍게 알아 간다. 사용자는 관리자 화면에서 파일을 열지 않고 항목을 추가·수정·삭제한다.

## 2. 목표 · 비목표 · 반목표

**목표**
- `Side B` 페이지를 추가한다. 경로는 `/side-b`(ko), `/en/side-b`(en)이다. 헤더 메뉴에는 넣지 않는다. 진입 링크는 §6에 적었다.
- 정사각형 커버 카드를 그리드로 보여 준다. 앞면은 커버와 그 위에 겹친 종류·제목·가수, 뒷면은 장르·좋아하는 이유·듣기 링크다.
- 카드를 누르면 대각선으로 뒤집히고, 마우스를 올리면 살짝 기울어진다.
- `/admin`에서 항목을 관리한다. 커버 업로드도 관리자 화면에서 한다.

**비목표**
- 재생기 삽입(iframe·오디오 미리듣기). 외부 서비스 임베드는 정적·경량 원칙과 맞지 않는다. 듣기는 외부 링크로만 제공한다.
- 외부 API로 커버나 메타데이터를 자동으로 가져오는 기능. 런타임 fetch를 금지하는 CRITICAL 규칙에 걸린다.
- 사이트 검색(pagefind)과 RSS에 항목을 노출하는 것.
- 노래 제목·가수명 번역.

**반목표** (기술적으로 돌아가도 실패로 본다)
- 사이트의 잔잔한 분위기를 깨는 과한 모션. 기울기는 최대 6°이고 빛 반사는 넣지 않는다.
- 뒷면 글이 잘리거나 읽을 수 없게 되는 것.
- JS가 없거나 모션 줄이기를 켠 사람이 뒷면 정보를 볼 수 없게 되는 것.
- 다른 페이지의 JS 무게가 늘어나는 것.
- 깨진 링크나 깨진 이미지가 배포되는 것.
- 관리자가 커버를 지워 빌드가 죽는 것.

## 4. 데이터

**[작성자 결정]** 데이터는 `src/config/music.ts`의 `MUSIC` 배열에 둔다. `profile.ts`와 같은 구조이며, 관리자의 범용 코드 생성기(`admin/server/codegen/configs.mjs`의 `writeDeclaration`)가 수정 없이 이 선언을 다시 쓸 수 있다.

```ts
interface MusicEntry {
  kind: 'song' | 'album';
  title: string;                 // 원어 그대로 (번역 안 함)
  artist: string;                // 원어 그대로
  album?: string;                // kind === 'song'일 때 수록 앨범 (선택)
  year?: string;                 // 'YYYY' (선택)
  cover?: string;                // src/assets/side-b/ 안의 파일명. 없으면 대체 커버
  genres: string[];              // 0개 이상. 번역 안 함
  note?: Localized<string>;      // 좋아하는 이유. ko/en 따로 쓰거나 한 값
  listenUrl?: string;            // http(s)만
}
```

- **[작성자 결정] 순서**: 배열 순서를 그대로 쓴다. 관리자에서 위·아래로 옮길 수 있다. 새 항목은 기존 `RepeatableList` 동작대로 맨 아래에 추가된다.
- **[작성자 결정] 언어 대체**: `note`는 수강 과목·수상과 같은 규칙을 쓴다. 현재 언어 값이 비면 다른 언어 값으로 대체하고, 둘 다 비면 이유 줄을 생략한다.
- **[작성자 결정] 빈 항목**: 제목이 빈 항목은 화면에서도 관리자 저장에서도 버린다.
- **[작성자 결정] 이유 길이**: 최대 140자. 관리자 입력에서 막는다. 뒷면은 정사각형이라 길이 상한이 있어야 글이 잘리지 않는다.

## 5. 커버 이미지

- **[작성자 결정] 위치**: 커버는 `src/assets/side-b/`에 둔다. 페이지는 `import.meta.glob('../assets/side-b/*.{jpg,jpeg,png,webp,avif,gif}', { eager: true })`로(업로드 허용 확장자에서 SVG만 뺀 것과 같다) 파일명을 키로 찾고 `astro:assets`의 `<Image>`로 그린다. 하위 폴더로 분리한 이유는 두 가지다.
  1. glob이 글 본문 이미지까지 끌어오지 않는다.
  2. 관리자의 "이미지" 화면은 `src/assets/` 최상위만 다루고 "사용 중" 판정이 글만 검사한다. 하위 폴더에 두면 그 화면에서 커버가 지워져 빌드가 죽는 경로가 생기지 않는다.
- **업로드**: 관리자 Side B 화면의 각 행에 드롭존을 둔다. 기존 `uploadFile`/`initDropZone`을 재사용하고, 서버의 `POST /assets`에 새 `purpose: 'music-cover'`를 추가해 `src/assets/side-b/`에 저장한다. 파일 검사(8MB, SVG 거부, 내용·확장자 일치)와 이름 규칙은 기존 것을 그대로 쓴다.
- **[작성자 결정] 정리**: Side B를 저장할 때 `src/assets/side-b/` 안에서 어떤 항목도 참조하지 않는 파일을 지운다. 자동 삭제는 관리자만 쓰는 이 폴더로 한정한다.
- **커버가 없거나 파일을 찾지 못할 때**: 빌드를 죽이지 않는다. 경고를 남기고 대체 커버를 그린다. 대체 커버는 토큰 색 배경에 제목 첫 글자다.
- **크기**: 그리드 칸 폭에 맞춰 `widths`/`sizes`를 지정한다. 첫 줄은 `loading="eager"`, 나머지는 lazy.

## 6. 페이지

- **라우트**: `src/pages/side-b.astro`와 `src/pages/en/side-b.astro`. 둘 다 `<SideBView />`만 렌더하는 세 줄짜리 파일로, archive와 같은 패턴이다. 뷰는 `src/components/views/SideBView.astro`이고 `ListLayout path="/side-b"`를 쓴다.
- **헤더 문구**: 제목은 `Side B`. 부제는 i18n `UI` 사전에 두고, 문구는 사용자가 나중에 바꿀 수 있다.
  - ko: "공부 기록의 뒷면 — 요즘 자주 듣는 노래와 앨범" **[작성자 결정]**
  - en: "The flip side of my study log — songs and albums on repeat" **[작성자 결정]**
- **[작성자 결정] 그리드**: `repeat(auto-fill, minmax(260px, 1fr))`, 간격은 기존 카드 그리드 토큰을 따른다. 카드는 `aspect-ratio: 1`이고 크기는 다음과 같다.
  - 375px: 1열, 약 343px
  - 768px: 2열
  - 데스크톱(1120px 컨테이너): 3열, 약 340px

  처음 안의 200px 최소폭으로는 한국어 140자 이유가 데스크톱 4열 카드(약 250px) 뒷면에 들어가지 않았다(검토에서 지적). 260px로 올리면 어느 폭에서도 카드가 약 260px 이상이다.
- **[작성자 결정] 뒷면 수용**: 뒷면 본문은 `--text-small`(14px)로 쓴다. 장르 칩은 뒷면에 최대 3개까지만 보인다. 전체 장르는 필터에 다 반영된다. 그래도 넘치면 뒷면 안에서만 세로 스크롤된다. 이것은 안전장치이고, 140자·칩 3개·260px 카드 조합에서는 스크롤이 생기지 않아야 한다(검증 항목).
- **빈 상태**: `MUSIC`이 비면 페이지에는 기존 `EmptyState`를 쓰고, 아래 진입 링크 두 곳을 모두 숨긴다 **[작성자 결정]**.
- **진입 링크**: 헤더 메뉴에는 넣지 않는다(사용자 결정). 대신 두 곳에 레코드 아이콘(`lucide:disc-3`) 링크를 둔다 **[작성자 결정]**.
  - 홈 `ProfileCard`의 소셜 아이콘 줄 끝
  - `SiteFooter`의 아이콘 줄(RSS 앞)

  둘 다 접근 가능한 이름은 "Side B — 좋아하는 음악"/"Side B — music I love"이고, 내부 링크이므로 새 탭으로 열지 않는다. 헤더(`SiteHeader`·`site.ts`·`navOrder`)는 손대지 않는다.
- 카테고리 id로 `side-b`를 쓰면 라우트가 충돌하므로 `categories.ts`의 주석에 예약어로 적는다.
- **문자열**: 종류 라벨(노래/앨범·Song/Album), 듣기 링크 라벨, "뒷면 보기"/"앞면으로" 접근성 라벨은 전부 `UI` 사전에 둔다. 컴포넌트에 직접 쓰지 않는다.
- **SEO**: 일반 페이지 메타(title·description·canonical·hreflang)는 기존 레이아웃을 따른다. pagefind 색인에서는 제외한다.

## 6-1. 장르 필터

사용자 요청: 그리드 위쪽에 장르를 보여 주고, 장르를 누르면 그 장르의 카드만 남긴다.

- **장르 목록**: 별도 목록을 두지 않고 모든 카드의 `genres`를 모아서 만든다. **[작성자 결정]**
  - 장르를 따로 관리하면 카드에 없는 장르나 카드에만 있는 장르가 생겨 어긋난다.
  - 같은 장르 판정은 대소문자와 앞뒤 공백을 무시한다. 표시는 처음 나온 표기를 쓴다.
  - 정렬은 많이 붙은 순서, 같으면 처음 나온 순서. **[작성자 결정]**
  - 칩 옆에 개수는 붙이지 않는다. **[작성자 결정]**
- **모양**: 헤더 아래, 그리드 위에 칩을 가로로 나열한다. 맨 앞은 "전체"/"All"이고 처음에는 "전체"가 선택돼 있다.
  - 640px 이상: 넘치면 줄을 바꾼다.
  - 640px 미만: 한 줄로 두고 가로로 스크롤한다 **[작성자 결정]**. 장르가 15~30개면 줄바꿈 시 칩만 5~8줄이 되어 첫 카드가 화면 밖으로 밀린다(검토에서 지적). 스크롤 줄 끝은 잘려 보이게 두어 더 있다는 것을 알린다.
- **레이아웃 이동 방지**: 필터 줄은 서버에서 그려 두고, JS가 없을 때만 숨긴다(`<html>`에 붙는 클래스가 없을 때 숨김, 또는 `<noscript>` 스타일). 스크립트가 시작된 뒤 줄을 끼워 넣어 그리드가 밀리는 일이 없어야 한다.
- **선택 방식**: 한 번에 장르 하나만 고른다. 이미 고른 칩을 다시 누르면 "전체"로 돌아간다. **[작성자 결정]** 여러 장르를 고르는 방식은 카드가 몇십 장 수준일 때 얻는 것보다 설명할 것이 많다.
- **동작**:
  - 고른 장르가 없는 카드는 숨긴다. 숨기는 순간에는 애니메이션을 넣지 않는다. 남은 카드에는 짧은 페이드만 준다. **[작성자 결정]** 레이아웃이 크게 출렁이는 재배치 모션은 반목표의 "과한 모션"에 해당한다.
  - 필터를 바꾸면 뒤집혀 있던 카드는 앞면으로 돌린다.
  - 모션 줄이기를 켠 경우에는 페이드 없이 즉시 바뀐다.
- **상태 보존**: 고른 장르를 주소의 해시에 남긴다. 값은 장르의 **비교 키**(소문자, 앞뒤 공백 제거)를 `encodeURIComponent`한 것이다. 예: `#genre=indie%20rock`, `#genre=r%26b`, `#genre=%EB%B0%9C%EB%9D%BC%EB%93%9C`. 같은 장르 판정과 주소가 같은 키를 쓰므로 두 장르가 한 주소로 겹치지 않는다 **[작성자 결정]**. 해시에 모르는 장르가 오면 "전체"로 연다. 필터를 바꿀 때는 `history.replaceState`를 써서 브라우저 뒤로 가기 기록을 쌓지 않는다. 새로고침하거나 링크를 공유해도 같은 필터로 열린다. **[작성자 결정]** 쿼리스트링이 아니라 해시인 이유는 정적 사이트라 서버가 다른 페이지를 내줄 수 없고, 같은 문서를 가리켜야 canonical이 흐트러지지 않기 때문이다.
- **접근성**:
  - 칩은 `<button aria-pressed>`이고, 칩 묶음은 `role="group"`에 "장르로 거르기"/"Filter by genre" 라벨을 단다.
  - 필터를 바꾸면 `aria-live="polite"` 영역에 "Indie Rock — 5개" 같은 결과 수를 읽어 준다.
  - 칩도 터치 영역 44px 규칙을 지킨다.
- **장르가 하나도 없거나 카드가 2장 미만이면** 필터 줄 자체를 내지 않는다. **[작성자 결정]**
- **JS가 없을 때**: 필터 줄을 내지 않는다(누를 수 없는 버튼을 보이지 않는다). 카드는 모두 보인다.
- **관리자**: 장르 칩 입력에 지금까지 쓴 장르를 제안 목록으로 보여 준다. `Indie rock`/`indie-rock` 같은 오타로 필터가 둘로 갈라지는 것을 줄이기 위해서다. **[작성자 결정]**

## 7. 카드 동작

### 마크업과 접근성
- 카드 하나는 앞면과 뒷면을 담은 요소다. 뒷면에 링크가 있어 카드 전체를 버튼 하나로 감쌀 수 없으므로(버튼 안에 링크는 무효), 각 면에 뒤집기 버튼을 따로 둔다.
  - 앞면: 면 전체가 `<button>`이다. 접근 가능한 이름은 "제목 — 가수, 자세히 보기" 형태다.
  - 뒷면: "앞면으로" `<button>`(44px 히트 영역)이 있다. 뒷면의 빈 곳을 클릭해도 앞면으로 돌아간다. 링크 클릭은 제외한다.
- 숨겨진 면에는 `inert`를 건다. 앞면일 때 뒷면의 듣기 링크로 Tab이 가지 않아야 한다.
- 키보드: Tab으로 카드에 가고 Enter/Space로 뒤집는다. 뒤집으면 포커스가 반대 면의 버튼으로 옮겨 간다. 방금 누른 버튼이 `inert`가 되어 포커스를 잃기 때문이다. 뒷면에서는 Tab으로 듣기 링크에 갈 수 있다.
- 듣기 링크는 `target="_blank" rel="noopener"`, 외부 링크 표시.
- 터치 영역 44px 규칙을 지킨다.

### 모션
- **뒤집기**: CSS `transform` 전환. JS는 클래스와 `aria-pressed`만 토글한다.
- **기울기**: `pointermove`로 `rotateX/rotateY`를 계산한다. 최대 6°, `pointerleave`에서 0으로 돌아오며 전환은 약 0.25s ease-out. `requestAnimationFrame`으로 묶어 프레임당 한 번만 쓴다. 기울기는 바깥 래퍼에, 뒤집기는 안쪽 카드에 둬서 둘이 겹쳐도 충돌하지 않는다.
- **기울기 조건**: `(hover: hover) and (pointer: fine)`일 때만 켠다. 휴대폰에서는 뒤집기만 한다.
- **모션 줄이기 (`prefers-reduced-motion: reduce`)**: 기울기를 끄고, 뒤집기는 회전 없이 즉시 면이 바뀐다.
- **진입 리빌**: 카드 그리드에 기존 `data-reveal-group`을 붙여 사이트의 다른 목록과 같은 스태거 리빌을 쓴다. 새 모션 코드는 만들지 않는다.

### JS 범위
- 스크립트는 `src/scripts/side-b.ts` 하나이고, `SideBView` 안의 `<script>`로만 불러온다(PostLayout의 페이지 전용 스크립트 패턴). anime.js는 쓰지 않는다. 다른 페이지의 번들에는 1바이트도 추가하지 않는다.
- **JS가 없을 때**: 뒷면 정보(장르·이유·링크)를 읽을 수 있어야 한다. 구현 방식은 빌더가 정한다. 예를 들어 JS가 붙기 전에는 뒷면을 카드 아래에 펼쳐 두고, 스크립트가 시작되면 뒤집기 모드로 바꾸는 방식이 가능하다. 단 그 전환이 화면 깜빡임이나 레이아웃 이동을 만들면 안 된다. 2026-08-21 모션 깜빡임 결함과 같은 류다.

### 듣기 링크 라벨
- **[작성자 결정]** 주소의 호스트로 서비스 이름을 정한다.

  | 호스트 | 라벨 |
  | --- | --- |
  | `youtube.com`, `youtu.be` | YouTube |
  | `music.youtube.com` | YouTube Music |
  | `open.spotify.com` | Spotify |
  | `music.apple.com` | Apple Music |
  | `melon.com` | Melon |
  | 그 밖 | 일반 "듣기"/"Listen" |

  이 판정은 순수 함수로 `src/lib/music.ts`에 둔다. 관리자 화면은 같은 함수로 링크 칸 옆에 "→ Spotify" 같은 라벨만 보여 준다. 카드 전체 미리보기는 만들지 않는다 **[작성자 결정]**.
- **스킴 없는 값**: 저장할 때 `https://`를 붙인다. `socialHref`와 같은 정신이다. `http(s)`가 아닌 스킴은 관리자 저장 단계에서 거절한다.

## 8. 관리자 화면

- **새 화면**: `/admin/side-b`. 등록 지점은 네 곳이다: `admin/integration.mjs` `ADMIN_ROUTES`, `admin/server/middleware.mjs` `ROUTES`(`GET/PUT /side-b`), `admin/components/AdminNav.astro` `ITEMS`(아이콘 `lucide:disc-3` **[작성자 결정]**), `admin/labels.ts`.
- **화면 구성**: `RepeatableList`로 행을 반복한다. 행 하나의 필드는 다음과 같다.
  - 종류: select (노래/앨범)
  - 제목, 가수, 앨범(종류가 노래일 때만 보임), 연도: 텍스트 입력
  - 커버: 드롭존과 썸네일, "바꾸기"·"지우기"
  - 장르: chips (`initChips`)
  - 좋아하는 이유: `LocalizedField`, `max=140`, `multiline`
  - 듣기 링크: URL 입력
- **서버**: `admin/server/handlers/music.mjs`(신규). 읽기는 `ssrLoadModule`, 쓰기는 `writeDeclaration({ declName: 'MUSIC', preserveComments: true })`. 저장 전에 다음을 처리한다.
  - 빈 제목 행 제거
  - URL 정규화와 스킴 검사
  - `year` 형식 검사
  - 커버 파일 존재 확인
  - 미참조 커버 정리
- **제약**: 관리자 페이지는 `src/config/*`를 직접 import하지 않는다. 기존 규칙이다.
- **배제 게이트**: 기존 4겹 배제(관리자 코드가 프로덕션 `dist`에 섞이지 않게 하는 장치)를 그대로 지난다. 새 파일도 `admin/` 아래에만 둔다.

## 9. 스펙과의 관계 — 기록할 예외
